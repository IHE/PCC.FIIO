The following sections define the technical differences between the HL7 FHIR IPS 2.0.1 (UV realm) and each National Extension that is intended to derive from the UV realm for implementation. Only the elements that differ from the HL7 FHIR IPS are listed. The HL7 FHIR IPS 2.0.1 column states the cardinality, and an [SO] tag where IPS defines a Content Creator obligation, followed by that obligation. The National Extension column states the cardinality and, in brackets, the Must Support flag where the national extension defines one. Each entry in the Notes column begins with the nature of the change:

 - **Constrained**: the national extension is stricter than IPS.
 - **Added**: the national extension adds an element, slice, section, or extension that IPS does not define, permitted by the IPS open slicing.
 - **De-constrained**: the national extension is less strict than IPS.
 - **Replaces**: the national extension uses its own profile or value set in place of the IPS one.
 - **Expanded**: the national value set includes the IPS values plus additional national values.
 - **Guidance**: the national extension gives usage guidance without a structural constraint.
 - **Relationship not stated**: the national extension does not state how its value set relates to the IPS value set.

Please review the [Testing Approach for National Extensions](testplan.html#testing-approach-national-extensions) for the testing expectations.

#### United States Patient Care Summary (US-PCS) Constraints
The US-PCS Constraints for the USA Implementation of IPS are defined in the [United States Patient Care Summary (US-PCS) Implementation Guide, 1.0.0 STU 1](http://hl7.org/fhir/us/pcs/ImplementationGuide/hl7.fhir.us.pcs).

The following constraints are added to the minimum requirements established by the base IPS IG. Please review the [Aligning US-PCS Sections with IPS, C-CDA and US Core](https://hl7.org/fhir/us/pcs/en/general-guidance.html#aligning-us-pcs-sections-with-ips-c-cda-and-us-core) section of this IG for the detailed list of differences.
 - The FHIR resources in the Bundle **SHALL** conform to the [US Core Implementation Guide, 6.1.0, STU6](http://hl7.org/fhir/us/core/ImplementationGuide/hl7.fhir.us.core).
 - The Composition resource **SHALL** be conformant to the requirements of the [FHIR Clinical Document Composition Profile](http://hl7.org/fhir/uv/fhir-clinical-document/StructureDefinition/clinical-document-composition).

For an example FHIR document that conforms to both the HL7 FHIR IPS and the US-PCS constraints of this national extension, review the [US-PCS Example Patient Aaron Morales Bundle](Bundle-ex-Bundle-USPCS-Complete-Aaron-Morales.html).
